# Benchmarks

## Known planets

`known_planets.csv` is the known-planet set: the positive controls that `tess-hunt benchmark known` must recover at
their catalog periods, with known-planet masks off.

It was generated by `tess-hunt targets known` in production run `20261009T164114Z-targets-4b349b4-1811`, from the
catalog snapshot of 2026-10-09 (UTC), and approved by the maintainer on 2026-10-09. Regenerate it only through a new
run and a new approval.

### Selection rule

The thresholds below are those of `criteria/search-v1.toml`, which selected the set and scored M1's published benchmark
tables. The M2 reruns score the same set under `criteria/search-v2.toml`.

1. TOIs with TFOPWG disposition KP or CP, a period inside `[search]` `period_min_days` to `period_max_days`, and a
   catalog depth, epoch and duration.
2. The host passes sample A (`[sample]`) twice: on the ExoFOP stellar values, then on its TIC v8.2 values. The TIC
   cut is the one that defines the search sample.
3. The host has light curves at MAST in at least `[sample]` `min_sectors` sectors, including one from
   `recent_sector_min` to `recent_sector_max`.
4. Of the survivors, sorted by depth, `[benchmark]` `known_count` planets are taken at evenly spaced ranks, so the set
   runs from the shallowest to the deepest.
5. Pi Men c (TOI 144.01, TIC 261136679) is always included, as the single-sector smoke test.

A planet is `required` when its TOI "Planet SNR" is at least `[benchmark]` `required_recovery_snr`. The benchmark run
exits non-zero if any required planet is missed.

Times in the CSV are BTJD (BJD_TDB - 2457000); durations are in days.

## Eclipsing-binary control

`eb_control.csv` holds the real-data negative control for the vetting checks: a known eclipsing binary that a vet run
must not advance. It is a control input, not a criterion.

The row is TOI-188.01 (TIC 280830734) from the ExoFOP TOI table in the catalog snapshot of 2026-10-09 (UTC). ExoFOP
gives its TESS disposition as EB and its TFOPWG disposition as FP; the catalog comment notes an odd and even depth
difference in SPOC's S1-S69 search and its retirement by TFOP as an eclipsing binary.

The values are the catalog row's, converted the way the catalog loader converts them: the epoch from BJD to BTJD and
the duration from hours to days. The period (days) and depth (ppm) are unchanged. No `tess-hunt` command writes or
reads the file.

The published vet run
[`20261009T191134Z-vet-c7a2625-ce0e`](../results/benchmarks/20261009T191134Z-vet-c7a2625-ce0e/checks.json) vetted
this signal, with the period, epoch and duration rounded on the command line; its `provenance.json` records the
arguments. [Decision 0006](../docs/decisions/0006-red-noise-depth-errors.md) describes the run. Later runs of the
control should pass the file's full-precision values.

## Replay comparisons

`compare_replay.py` regenerates a replay comparison, `results/benchmarks/<replay run id>-comparison.md`, from the
replayed run's published `injections.csv` and the replay's, run from the repository root:
`uv run python benchmarks/compare_replay.py OLD_CSV NEW_CSV > results/benchmarks/<replay run id>-comparison.md`.
